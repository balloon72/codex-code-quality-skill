# 安全与性能重点检查

本文件只在改动涉及外部输入、认证授权、数据库、命令/文件、网络调用、性能路径或前端关键渲染时加载。

## 安全

### 输入边界

所有外部来源默认不可信：

- HTTP 参数/Body/Header
- 消息队列/Webhook
- 文件上传
- 第三方 API
- 配置和环境变量
- 日志/监控数据
- AI/Agent/工具返回内容

在系统边界做格式、长度、范围和语义验证。

### 注入

- SQL 使用参数化查询。
- Shell/CLI 避免字符串拼接；优先参数数组和白名单约束。
- 文件路径防止目录穿越。
- HTML/富文本按渲染场景编码/净化。
- URL/SSRF 场景限制协议、主机、内网目标和重定向策略（按系统安全要求）。

### 鉴权授权

- “已登录”不等于“有权操作该资源”。
- 服务端必须执行最终权限校验，不能只依赖前端隐藏按钮。
- 多租户/多空间数据访问必须校验资源归属。

### Secret

禁止把以下内容写入源码、日志、错误响应或前端：

- 密码
- API key/token
- Cookie/session
- 私钥
- 数据库凭据
- 云凭据

## 性能

### 数据库

重点检查：

- N+1
- 缺少分页/limit
- 循环逐条读写
- 大事务
- 重复查询同一数据
- 在内存中加载超大结果集再过滤

### 网络

- 独立请求不必要串行
- 缺少超时
- 无界重试
- 无界并发
- 同一请求重复访问相同外部资源

### CPU/内存

- hot path 重复 parse/serialize/regex compile
- 大对象/大集合反复复制
- O(n²) 扫描可用 Map/Set 降低复杂度

只有当规模足以产生实际影响时，才为算法复杂度引入额外数据结构。

### React

优先发现：

- async waterfall
- 重复数据请求
- 明显不必要的 rerender
- 巨大列表直接完整渲染
- 重型依赖进入首屏 bundle

不要把 `useMemo/useCallback` 数量当性能指标。

## 性能结论需要证据

能测量时优先：

- benchmark
- profiler
- query count
- explain plan
- bundle analyzer
- React profiler
- 请求耗时/调用次数

没有测量时，使用“存在结构性风险”“可能导致”之类准确措辞，不伪造性能收益数字。
